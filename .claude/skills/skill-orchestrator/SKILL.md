# Skill Orchestrator

## الشغل
قبل أي خطوة في `/ss`:
1. **Glob** `.claude/skills/*/SKILL.md` — اقرا كل المهارات المتاحة
2. **Parse** كل ملف: name + description
3. **Match** مع الطلب الحالي + السياق (هل قاري ملفات؟ هل بتكتب كود؟ هل أداء حساس؟) 
4. **Apply** المهارات اللي طلعت match (ممكن اتنين/تلاتة في نفس الوقت)

## أمثلة (قلّل الحاجات المعقدة)

**الطلب:** "اعملي أداة ويندوز بـ C#"
→ Match: `token-budget` (اختار haiku/sonnet), `context-diet` (قرا الملفات المهمة بس), `caveman` (رد مختصر)
→ Apply: خلي بالك توزيع الموديلات + قرا ذكي + رد قصير

**الطلب:** "فيه خطأ: RuntimeException..."
→ Match: `error-loop` (3 محاولات max), `known-issues` (تحقق أول)
→ Apply: شيك الأرشيف الأول، إلا لو مش موجود ابدأ debug

**الطلب:** "اكتب توثيق"
→ Match: `context-diet` (قرا ملفات المشروع الأساسية بس), `caveman` (ملخص قوي)
→ Apply: مش محتاج توثيق طويل

## الحد الأدنى (دايمًا)
```
caveman + token-budget + context-diet
```
دول الثلاثة بس — كل باقي المهارات optional حسب الحالة.

## الحظر (متشغّلش ده تلقائي)
```
self-improve, session-memo, cost-tracker
```
دول بتحتاج حكم يدوي — هم بيشتغلوا في نهاية المهمة، مش أثناءها.

## الخطأ اللي ممكن تقع فيه
ما تشغّلش مهارتين متعارضتين في نفس الوقت. مثال:
- مش ممكن `caveman` (رد قصير) + `frontend-design` (شرح تفصيل الألوان) معاً
- لو الطلب قال "اشرحلي" → تجاوز `caveman` تلقائي للمهمة دي بس
